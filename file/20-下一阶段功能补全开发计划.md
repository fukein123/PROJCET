# 下一阶段功能补全开发计划

更新时间：2026-03-14

版本：执行中

## 1. 阶段目标

本阶段围绕“社区志愿服务管理”主目标继续补全系统功能，重点不是再堆页面，而是把：

- 管理员后台
- 登录 / 注册
- 门户主页面
- 志愿者自助能力

这四条主链路彻底收口，并保证 CRUD、状态机、权限、统计和审计逻辑一致。

## 2. 已冻结规则

### 2.1 状态机

- 活动状态：`PUBLISHED -> ONGOING -> ENDED`，支持归档 `ARCHIVED`
- 报名状态：`PENDING -> APPROVED / REJECTED`
- 打卡状态：`SIGNED_IN -> FINISHED`
- 帖子审核状态：`PENDING -> APPROVED / REJECTED -> ARCHIVED`
- 认证审核状态：`NOT_SUBMITTED -> PENDING -> APPROVED / REJECTED`
- 订单状态：`CREATED -> SHIPPED -> RECEIVED`，或 `CREATED -> CANCELLED`

### 2.2 权限矩阵

- 游客：只浏览 `/portal/*`
- 志愿者：登录后进入门户与 `/portal/me/*`
- 管理员：登录后只进入 `/admin/*`
- `/volunteer/*`：仅保留过渡跳转

### 2.3 上传规则

- 活动图、帖子封面、轮播图、商品图、头像：统一图片格式与大小限制
- 身份证图片：单独目录、受控访问、不允许匿名直链

### 2.4 数据校验

- 禁止空标题、空正文、空分类、空图片等脏数据提交
- 时间区间必须合法
- 人数、积分、库存不得为负或无效

### 2.5 删除语义

- 活动、动态、公告、帖子、商品、用户：优先归档 / 停用
- 评论、轮播图、无效测试数据：允许物理删除

### 2.6 留痕与统计

- 审核报名、审核帖子、审核认证、归档内容、修改订单状态统一进入审计日志
- 后台统计口径保持固定，避免列表与图表对不上

## 5. 本轮验收基线

- 后端：`mvn -DskipTests compile`
- 后端关键测试：删除语义、状态机、权限边界

- 前端构建：`npm run build`
- 浏览器验收：使用 `playwright` 对门户与关键路由做真实页面检查
