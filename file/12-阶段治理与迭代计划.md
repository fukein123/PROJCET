# 阶段治理与迭代计划

更新时间：2026-03-12

## 1. 当前判断

项目已经具备可运行的前后端分离基础，但还存在三类问题：

- 结构问题：部分文档和配置仍沿用旧目录名 `admin/`，与当前仓库实际结构 `Frontend/` 不一致。
- 代码问题：分页查询、状态映射、图片上传校验在多个页面重复实现，前端脚本偏重。
- 仓库问题：项目内 `skills/` 目录包含与当前主链路无关的 skill，维护成本偏高。

## 2. 本轮目标

1. 收敛项目结构与命名，统一前后端边界。
2. 删除明确未使用代码和无效结构。
3. 抽取前端共用能力，降低页面重复逻辑。
4. 精简本地 skill，只保留核心 skill。
5. 完成构建和运行验证。

## 3. 分阶段执行

### 阶段 A：结构盘点

- 审核根目录、前端、后端与 `file/` 文档的一致性。
- 对照需求文档确认当前功能缺口和结构风险。

### 阶段 B：前端公共能力下沉

- 统一分页查询逻辑。
- 统一状态文案与标签展示。
- 统一图片上传校验。

### 阶段 C：仓库清理

- 删除未使用组件和无效字段。
- 精简项目内 `skills/`。
- 修正文档与部署配置中的旧目录名。

### 阶段 D：验证

- 前端执行 `npm run build`。
- 后端执行 `mvn -DskipTests compile` 或等价编译命令。
- 条件允许时执行冒烟验证。

## 4. 需求驱动说明

本项目仍以 `.spec-workflow/specs/community-volunteer-service-platform/requirements.md` 作为需求基线，但当前审批状态为 `pending`。  
因此，本轮先完成不会改变业务边界的结构治理与共性能力收敛；后续更大规模功能补足应在审批解除后继续推进。

## 5. 当前核心 skill 策略

- 保留：`frontend-design`、`webapp-testing`、`pdf`
- 移除：与当前主链路无关的设计扩展、日志分析、视频与安全专项 skill
- 原则：项目仓库内只保留高频使用的核心 skill，其余按需临时安装
