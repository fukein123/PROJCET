# 前后端分离结构说明

更新时间：2026-03-12

## 1. 根目录结构

```text
zero/
├─ Frontend/                   # 前端（Vue 3 + TS + Vite）
├─ backend/                    # 后端（Spring Boot + MyBatis-Plus）
├─ file/                       # 项目文档
├─ skills/                     # 项目内核心 skill
├─ .spec-workflow/             # 规格与实施记录
├─ README.md
└─ .gitignore
```

## 2. 前端分层（`Frontend/src`）

- `api/`：接口封装，按业务域拆分。
- `views/`：页面层，按角色与模块拆分。
- `components/`：可复用组件。
- `stores/`：状态管理（Pinia）。
- `router/`：路由与权限守卫。
- `utils/`：请求、鉴权、展示、上传、校验等工具。
- `composables/`：分页查询、门户跳转等复用逻辑。

## 3. 后端分层（`backend/src/main/java/com/community`）

- `common/`：配置、异常、工具、统一响应。
- `modules/auth`：登录注册。
- `modules/user`：用户与资料管理。
- `modules/activity`：活动、报名、审核、打卡。
- `modules/content`：动态、公告、论坛、评论、收藏。
- `modules/dashboard`：统计看板与周榜。
- `modules/schedule`：定时任务。

## 4. 前后端边界约定

- 前端只通过 `api/*` 调用后端 REST，不直接操作数据库。
- 后端 Controller 处理参数与权限，业务逻辑放在 Service。
- 统一响应使用 `ApiResponse`，分页统一使用 `PageResult`。
- 展示枚举、上传校验、分页查询等前端通用能力优先沉淀到 `utils/` 和 `composables/`，避免页面脚本重复膨胀。

## 5. skill 使用策略

- 仓库内只保留核心 skill：`frontend-design`、`webapp-testing`、`pdf`。
- 其他 skill 如确有需求，按会话环境临时安装，不再长期跟随项目源码分发。

## 6. 当前结构治理结论

- 目录边界已明确，但部分旧文档和配置仍使用过时的 `admin/` 路径，已在本轮统一更正。
- 前端管理页存在较多重复的分页、状态映射和上传校验逻辑，已开始下沉为共享能力。
- `.spec-workflow` 已存在需求规格，但当前需求审批仍处于 `pending`，后续设计与任务拆解需等待审批解除。
