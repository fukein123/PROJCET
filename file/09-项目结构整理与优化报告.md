# 深度重构观察报告（社区志愿服务平台）

更新时间：2026-03-13

## 1. 本轮重构范围

本轮重构围绕“社区志愿服务平台 + 前后端分离”两条原则，覆盖：

- 认证与门户交互：登录、退出、门户导航状态。
- 管理端治理能力：分类/活动/动态/公告/帖子/评论的批量删除。
- 志愿者体验：活动详情、收藏 CRUD、打卡记录可读性。
- 通用能力：图片上传（注册头像、活动封面、动态配图）。
- 去积分化：移除积分相关入口与统计展示。

## 2. 重构结果总览

### 2.1 架构一致性

- 后端新增通用上传接口：`/api/common/upload`，并由前端统一通过 `api/common.ts` 调用。
- 上传、收藏、批量删除等能力全部走后端 API，不在前端做“伪实现”。
- 数据结构扩展同步到实体、DTO、接口与页面，符合前后端分离边界。

### 2.2 业务语义一致性

- 门户已移除“积分兑换”入口；管理员首页改为“评论数量”指标。
- 评论列表侧过滤“自动化冒烟评论”字样，避免测试文案污染业务视图。
- 收藏模块由“仅增删”升级为“增删改查 + 批量删除”。

### 2.3 可维护性提升

- 管理端核心页面统一支持批量删除，减轻重复点击负担。
- 登录、注册、活动管理、内容管理关键页文案和交互统一中文。
- 管理员端与志愿者端采用更强差异化主题色，角色辨识度更高。

## 3. 关键技术变更

### 3.1 后端

- 新增：
  - `WebMvcConfig`：`/uploads/**` 静态资源映射。
  - `CommonController`：图片上传接口。
  - `IdListRequest`：批量删除统一入参。
  - `FavoriteRequest / FavoriteUpdateRequest`：收藏 CRUD 入参。
  - `CheckRecordView`：打卡记录扩展视图。
- 改造：
  - `ActivityService / ActivityController`：
    - 活动封面字段。
    - 分类与活动删除/批量删除。
    - 打卡记录输出活动名称、地点、距离、服务时长。
  - `ContentService / ContentController`：
    - 动态、公告、帖子、评论删除/批量删除。
    - 收藏模块 CRUD + 分页 + 批量删除。
  - `DashboardService`：统计项由 `orderCount` 改为 `commentCount`。
- 数据脚本：
  - `schema.sql` 增加扩展字段与兼容式条件变更逻辑。
  - `data.sql` 重建为 UTF-8 可执行种子数据，移除旧积分导向文案。

### 3.2 前端

- 新增 `api/common.ts`，统一上传图片。
- 页面改造：
  - `RegisterView`：结构重排 + 头像上传。
  - `LoginView`：中文化 + 验证码失败刷新。
  - `PortalNavBar`：退出后正确显示“登录”，移除积分入口。
  - `PortalActivitiesView`：活动详情展示增强 + 收藏入口。
  - `PortalNewsView`：动态检索、类型筛选、图文卡片与热门侧栏。
  - `ActivityCategoryView / ActivityManageView / ContentManageView`：批量删除与上传接入。
  - `VolunteerMyFavoritesView`：收藏 CRUD 全流程。
  - `VolunteerCheckRecordsView`：状态、距离、服务时长可读化。
- 样式与体验：
  - `MainLayout` 提升管理员端/志愿者端主题差异化。
  - 更新站点图标为社区志愿主题。

## 4. 风险与待优化项

1. 初始化链路已在 2026-03-13 `G4` 中切换到 `Flyway`；后续重点风险从“是否接入迁移框架”转为“后续增量变更是否继续遵守版本化迁移规范”。
2. 收藏模块已在 2026-03-13 `G2` 中补充活动标题、地点、时间快照字段，历史漂移风险已明显收敛。
3. 评论测试数据已在 2026-03-13 `G1` 中切换为 `test_data_tag` 显式标记，关键字误判风险已明显收敛。
4. 活动/动态/公告的批量归档与恢复已在 2026-03-13 `G3` 中补齐；论坛帖子/评论仍保留审核/删除语义，如需归档需单独设计状态机。

## 10. 数据库迁移目录边界补充（2026-03-13）

### 10.1 目录职责重新收口

- `backend/src/main/resources/db/init-database.sql`
  - 仅负责建库、建账号、授权。
  - 属于 DBA / 本地环境引导脚本，不属于应用运行期迁移链路。
- `backend/src/main/resources/db/migration/`
  - 作为应用运行期唯一有效的数据库迁移目录。
  - 当前职责拆分为：
    - `B1__baseline_schema.sql`：空库/新库基线建表
    - `V1__baseline_schema.sql`：历史版本 `1` 校验兼容保留
    - `V2__legacy_schema_alignment.sql`：旧库接入后的对齐补丁
    - `R__seed_reference_data.sql`：可重复执行的参考数据
    - `README.md`：迁移边界、执行顺序、回滚约束说明
- `backend/src/main/resources/db/schema.sql`
  - 已退役为占位说明，不再承担运行期建表职责。
- `backend/src/main/resources/db/data.sql`
  - 已退役为占位说明，不再承担运行期种子数据职责。
- `scripts/verify-flyway-clone.ps1`
  - 作为数据库迁移 live 验收统一入口，负责 clone 库创建、导入、启动和日志摘要。

### 10.2 当前执行顺序

1. 需要新建数据库或账号时，先由 DBA 或本地开发者手工执行 `init-database.sql`。
2. 应用启动后，统一由 Flyway 接管结构与参考数据迁移。
3. 空库路径固定为 `B1 -> V2 -> R`。
4. 非空旧库首次接入路径固定为 `BASELINE(1) -> V2 -> R`。
5. 已存在 `V1` 历史的环境继续走 `validate -> pending V* -> pending R*`。

### 10.3 结构治理结论

- 建库建账号、结构迁移、参考数据迁移、clone 验收四类职责已经拆开，不再共享同一入口。
- 后续数据库增量变更只能新增 `V*.sql` 或保持幂等的 `R*.sql`，不能回写 `schema.sql` / `data.sql`。
- 回滚边界固定为“DBA 备份恢复”或“新增前向修复迁移”，不再接受手工重放旧初始化 SQL 的做法。
