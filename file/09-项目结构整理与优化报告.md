# 深度重构观察报告（社区志愿服务平台）

更新时间：2026-03-12

## 1. 本轮重构范围

本轮重构围绕“社区志愿服务平台 + 前后端分离”两条原则，覆盖：

- 认证与门户交互：登录、退出、门户导航状态。
- 管理端治理能力：分类/活动/动态/公告/帖子/评论的批量删除。
- 志愿者体验：活动详情、收藏 CRUD、打卡记录可读性。
- 通用能力：图片上传（注册头像、活动封面、动态配图）。
- 去积分化：移除积分相关入口与统计展示。

## 2. 重构结果总览

### 2.1 架构一致性

- 后端新增通用上传接口：`/api/common/upload`，并由前端统一通过 `api/common.ts` 调用。
- 上传、收藏、批量删除等能力全部走后端 API，不在前端做“伪实现”。
- 数据结构扩展同步到实体、DTO、接口与页面，符合前后端分离边界。

### 2.2 业务语义一致性

- 门户已移除“积分兑换”入口；管理员首页改为“评论数量”指标。
- 评论列表侧过滤“自动化冒烟评论”字样，避免测试文案污染业务视图。
- 收藏模块由“仅增删”升级为“增删改查 + 批量删除”。

### 2.3 可维护性提升

- 管理端核心页面统一支持批量删除，减轻重复点击负担。
- 登录、注册、活动管理、内容管理关键页文案和交互统一中文。
- 管理员端与志愿者端采用更强差异化主题色，角色辨识度更高。

## 3. 关键技术变更

### 3.1 后端

- 新增：
  - `WebMvcConfig`：`/uploads/**` 静态资源映射。
  - `CommonController`：图片上传接口。
  - `IdListRequest`：批量删除统一入参。
  - `FavoriteRequest / FavoriteUpdateRequest`：收藏 CRUD 入参。
  - `CheckRecordView`：打卡记录扩展视图。
- 改造：
  - `ActivityService / ActivityController`：
    - 活动封面字段。
    - 分类与活动删除/批量删除。
    - 打卡记录输出活动名称、地点、距离、服务时长。
  - `ContentService / ContentController`：
    - 动态、公告、帖子、评论删除/批量删除。
    - 收藏模块 CRUD + 分页 + 批量删除。
  - `DashboardService`：统计项由 `orderCount` 改为 `commentCount`。
- 数据脚本：
  - `schema.sql` 增加扩展字段与兼容式条件变更逻辑。
  - `data.sql` 重建为 UTF-8 可执行种子数据，移除旧积分导向文案。

### 3.2 前端

- 新增 `api/common.ts`，统一上传图片。
- 页面改造：
  - `RegisterView`：结构重排 + 头像上传。
  - `LoginView`：中文化 + 验证码失败刷新。
  - `PortalNavBar`：退出后正确显示“登录”，移除积分入口。
  - `PortalActivitiesView`：活动详情展示增强 + 收藏入口。
  - `PortalNewsView`：动态检索、类型筛选、图文卡片与热门侧栏。
  - `ActivityCategoryView / ActivityManageView / ContentManageView`：批量删除与上传接入。
  - `VolunteerMyFavoritesView`：收藏 CRUD 全流程。
  - `VolunteerCheckRecordsView`：状态、距离、服务时长可读化。
- 样式与体验：
  - `MainLayout` 提升管理员端/志愿者端主题差异化。
  - 更新站点图标为社区志愿主题。

## 4. 风险与待优化项

1. 当前 SQL 初始化依赖 MySQL 本地版本，生产环境建议改为 Flyway/Liquibase 管理迁移。
2. 收藏模块当前仍以 `activityId` 为主关联键，后续可增加活动快照字段，减少历史数据漂移。
3. 评论过滤规则目前基于关键字，后续可引入“测试数据标记字段”替代文本过滤。
4. 管理端批量删除已覆盖核心模块，后续可补充“批量恢复/归档”能力。

## 5. 验证结论

- 前端构建：`npm run build` 成功。
- 后端编译：`mvn -DskipTests compile` 成功。
- 自动化冒烟：登录、报名、评论、退出链路全部通过。

结论：本轮改造已完成需求闭环，并具备继续迭代的结构基础。

## 6. zero2.0 追加重构观察（2026-03-12）

1. 分页基础设施统一为 PageHelper，活动、用户、内容、评论、收藏、报名、打卡记录分页逻辑已统一，降低了页面规模扩大后的维护成本。
2. 活动模型从“经纬度定位驱动”转为“内容与服务组织驱动”，新增 `content`、`volunteerQuota`，删除活动经纬度字段，业务语义更贴合社区志愿服务场景。
3. 活动报名审核返回结构升级为 `ActivityApplicationView`，管理端已能直接识别“哪个活动 + 哪位志愿者 + 当前状态”，减少误审风险。
4. 志愿者活动中心已形成“列表 → 详情 → 评价”闭环，活动评价支持按活动 ID 维度分页查询，为后续口碑统计和质控打基础。
5. 注册与用户管理已完成“志愿者身份信息优先”的交互重构，字段顺序和文案语义与业务目标一致，减少无效输入。
